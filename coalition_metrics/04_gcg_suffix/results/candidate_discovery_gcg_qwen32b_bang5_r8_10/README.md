# Qwen multi-context GCG: first result

## Short interpretation

The run optimized a suffix beginning with `!!!!!`. It used 15 training
contexts (runs 0–4, rounds 8–10) and 12 validation contexts (runs 12–15,
rounds 8–10), keeping the complete game as the resampling unit.

The first gradient-ranked coordinate replacements were rescored over all
training contexts. `网` had the lowest training KL among the first four
candidates and also improved validation KL, so the validation-best suffix was
set to that one-token string. Two subsequent coordinate steps did not produce
a new validation best, so the convergence rule stopped the search after three
steps. Candidate strings from the tokenizer may look accidental; their text
does not imply a meaningful natural-language instruction.

| Split | Empty suffix | Selected suffix `网` | KL reduction |
|---|---:|---:|---:|
| Training mean context KL | 34.726 nats | 31.658 nats | 4.426 bits |
| Validation mean context KL | 41.407 nats | 39.620 nats | 2.579 bits |

The validation gain was positive on three of four complete games. The pooled
soft MI diagnostic stayed at about 0.90457 bits. The optimization targets
closeness to the no-channel move distributions; it does not directly minimize
MI. The result does not establish a change in full-game scores or
`I(A;B|S)`.

## Files

- `qwen32b_gcg_bang5_r8_10_runs0_4_val12_15.md`: every GCG step and candidate
  loss, plus the report generated by the Modal job.
- `qwen32b_gcg_bang5_r8_10_runs0_4_val12_15.json`: full context-level
  probabilities, losses, run/round IDs, gradients, and stop reason.
- `RESULTS_INTERPRETATION.md`: plain-language interpretation, per-run result,
  bootstrap interval, individual A/B KL, and limitations.
- `train_cases_and_prompts.json` and `validation_cases_and_prompts.json`:
  reconstructed prompts used to create the distributions.
- `selected_candidate_prompts.json`: the exact optional-channel prompt content
  with `网` appended for every train/validation run, round, and seat.

## Open the prompt that was scored

The candidate prompt is stored as a system message plus the full user message
with `\n\n网` appended at the end. The probability probe then continues with the
assistant prefix `MOVE: ` so the model's legal-move probabilities can be
measured. To print one example (validation run 12, round 8, seat A):

```bash
jq '.[] | select(.split == "validation" and .run == 12 and .round == 8 and .seat == "A") |
  {suffix, suffix_token_ids, system_prompt, user_prompt_with_candidate_suffix,
   assistant_prefix_for_probability_probe}' \
  coalition_metrics/04_gcg_suffix/results/candidate_discovery_gcg_qwen32b_bang5_r8_10/selected_candidate_prompts.json
```

To inspect the prompts prepared before suffix insertion, open the corresponding
entry in `validation_cases_and_prompts.json` and read `system_prompt` and
`user_prompt_without_suffix`. The GCG report's `run` and `round` fields identify
the matching context. Qwen's chat template adds its message-boundary tokens
around these contents at inference time.

The no-channel and optional-channel prompts share run and round labels but
come from separate trajectories, so their public histories are not exactly
matched. The KL gain is an optimization surrogate, not a causal estimate.
